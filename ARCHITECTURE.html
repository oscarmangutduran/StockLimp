1.Resumen Ejecutivo y Topología Global

StockLimp es una plataforma de software integral diseñada para la gestión logística de aprovisionamiento de productos de limpieza industrial, control horario de operarios (fichajes con justificantes médicos/laborales), administración de solicitudes de vacaciones por días hábiles y trazabilidad de rutas hacia centros de trabajo asignados.

Frontend Multiplataforma

Construido sobre Expo 54 y React Native Web (React 19) con Expo Router 6. Proporciona una interfaz unificada adaptativa (Web escritorio, tablet y móvil Android/iOS) con animaciones nativas y gráficos SVG vectoriales.

Backend RESTful API

Desarrollado en PHP 8.3 / Laravel. Gestiona transacciones ACID concurrentes, políticas de autorización basadas en roles (RBAC), cola de envíos de correo asíncronos y generación de hojas de cálculo Excel XLSX.

Persistencia y Almacenamiento

Motor MySQL 8.0 (InnoDB) con integridad referencial estricta y llaves foráneas. Almacenamiento de fotos de perfil en Base64 procesadas en disco local y justificantes en el sistema de archivos de Laravel Storage.

2.Flujos de Datos de Entrada y Salida (E/S)

El sistema se rige por un esquema asíncrono cliente-servidor mediante peticiones HTTP estructuradas en formato JSON y multipart/form-data. A continuación se desglosan los ciclos de vida de datos fundamentales:

2.1. Ciclo de Autenticación y Recuperación de Acceso

Secuencia de Login y Verificación de Estado
  1. Entrada: El operario introduce email y password en HomeScreen.
  2. Procesamiento Backend: UserController::login busca al usuario por email. Comprueba el hash de contraseña utilizando Hash::check() para hashes Bcrypt ($2y$) y coincidencia directa para credenciales heredadas.
  3. Validación de Estado:
    • Si el estado es pendiente, retorna error HTTP 403: "Tu cuenta está pendiente de aprobación por el Super Administrador".
    • Si el estado es rechazado, retorna error HTTP 403.
    • Si la contraseña es la temporal por defecto (12345), devuelve debe_cambiar_password: true bloqueando el acceso a módulos operativos hasta que ejecute el cambio obligatorio.
  4. Salida & Persistencia: El backend devuelve el payload del usuario (ID, nombre, email, rol, ID de centro asignado). En navegador Web, el cliente lo graba en sessionStorage.setItem('user') manteniendo la sesión al recargar sin comprometer tokens en cookies inseguras.

2.3. Ciclo de Control Horario (Fichajes y Justificantes)

  • Consulta de Estado Inicial (POST /api/fichajes/actual): Al abrir la pantalla de fichaje, se consulta el último registro sin cerrar (estado trabajando o en_pausa). Si existe, el cronómetro frontend sincroniza el tiempo transcurrido desde hora_entrada.
  • Inicio de Turno (POST /api/fichajes/iniciar): Registra fecha y hora exacta del servidor en UTC/local mediante Carbon, evitando discrepancias de hora del reloj del dispositivo cliente.
  • Pausa/Reanudación (POST /api/fichajes/pausar): Cambia entre los estados trabajando y en_pausa de forma inmediata.
  • Cierre con Documentos (POST /api/fichajes/finalizar): Petición con soporte para subida de ficheros (multipart/form-data). Guarda el fichero en storage/app/public/justificantes y vincula la URL pública al registro del fichaje junto con observaciones.

2.4. Ciclo de Solicitud y Cómputo de Vacaciones

El sistema incluye un motor algorítmico en VacacionController::calcularDiasLaborables que itera día por día entre la fecha inicial y la fecha final, evaluando $current->isWeekday() para descartar sábados y domingos. Los operarios cuentan con un cupo anual de 22 días laborables; si la suma de solicitudes aprobadas o pendientes excede el límite, la API rechaza la solicitud de forma preventiva.

5.Componentes Frontend y Manejo de Estado

El frontend implementa una arquitectura basada en componentes desacoplados con Expo Router y persistencia en SessionStorage. A continuación se analiza cada componente clave:

HomeScreen (src/app/index.tsx) • Orquestador y Auth Guard

Es la vista raíz que gestiona el enrutamiento interno. Si no hay sesión, despliega el panel de Login y el botón flotante del Asistente Virtual (Chatbot inteligente). Tras autenticar al usuario, renderiza el Sidebar de navegación y monta dinámicamente la pestaña adecuada según el rol.

Roles Administrativos (super_admin / admin):
Acceso completo a Centros, Productos, Pedidos, Panel de Control, Aprobación de Usuarios, Vacaciones y Analítica.
Rol Empleado / Operario (usuario):
Acceso limitado exclusivamente a Pedidos (sólo suyos y en días 2-8), Control Horario (Fichaje + Vacaciones) y Perfil.

Desglose de Vistas Principales (Dashboard Views)

1. OrdersView (src/components/dashboard/OrdersView.tsx)

El módulo más extenso de la aplicación. Implementa:

  • Filtros por Operario y Rutas: Búsqueda en tiempo real con animación de barra expansible y filtro por número de ruta.
  • Acciones Masivas: Casillas de verificación para marcar múltiples pedidos y cambiar su estado en lote (por ejemplo, a ENTREGADO) con confirmación mediante modal personalizado.
  • Ventana Temporal Restringida: Modal de advertencia que impide a operarios modificar pedidos fuera de los días 2 al 8 de cada mes, con botón de bypass para pruebas de administración.
  • Exportación XLSX: Descarga directa del libro de pedidos formateado con cabecera y desglose de líneas.
2. TimeTrackingView (src/components/dashboard/TimeTrackingView.tsx)

Gestiona la jornada laboral diaria del operario:

  • Cronómetro SVG Circular: Dibuja anillos de progreso vectoriales interactivos calculando horas y minutos trabajados respecto a la jornada diana (8 horas).
  • Subida de Justificantes: Selector de documentos (PDF o imágenes) mediante expo-document-picker para adjuntar partes de baja médica o justificaciones de retraso.
  • Calendario de Vacaciones: Modal con react-native-calendars configurado en español. Permite seleccionar fecha inicio y fecha fin, calculando al vuelo los días hábiles restantes.
3. AnalyticsView (src/components/dashboard/AnalyticsView.tsx)

Motor de inteligencia de negocio para almacén y compras:

  • Agregación Dinámica: Cruza los pedidos con sus detalles y productos sumando unidades consumidas en el año o mes seleccionado.
  • Gráficos Vectoriales Propios: Gráfico de donut/pastel SVG con porcentajes de cuota por producto y gráfico de barras comparativo mensual (2025 vs 2026).
  • Resiliencia Offline: Incluye dataset histórico simulado (MOCK_MONTHLY_DATA) para visualización inmediata si el servidor API está inaccesible.
4. ControlPanelView.tsx

Permite a los administradores gestionar el listado completo de operarios, cambiar roles en caliente, vincular usuarios a centros de trabajo y detonar el restablecimiento de contraseñas por correo.

5. VacationsAdminView.tsx

Bandeja de entrada donde el departamento de RRHH o Administración aprueba, rechaza o cancela las solicitudes de vacaciones emitidas por los operarios de plantilla.

6. ApproveUsersView.tsx

Flujo de admisión de personal: interfaz doble donde los administradores invitan nuevos usuarios y el Super Admin autoriza o rechaza los registros pendientes.

7. ProfileView.tsx

Edición de información personal y carga de foto de perfil con recorte/conversión a Base64 y validación de tamaño máximo en cliente (5 MB).

6.2. Infraestructura Docker Compose y Cloud Render

El proyecto se encuentra totalmente contenedorizado para despliegues locales e integración continua:

Definición de Servicios en docker-compose.yml
  • stocklimp-db: Imagen mysql:8.0 en puerto 3306 con volumen persistente dbdata.
  • stocklimp-back: Contenedor PHP/Laravel compilado vía Dockerfile propio, ejecutándose en el puerto 8000 y enlazado con la red de base de datos.
  • stocklimp-front: Contenedor Node.js que ejecuta Expo Web en el puerto 8081 con soporte para polling de cambios en caliente (CHOKIDAR_USEPOLLING=true).
Despliegue en la Nube (render.yaml)

Configurado con dos servicios principales: stocklimp-backend como Web Service en entorno PHP / Docker y stocklimp-db como base de datos administrada. El frontend en producción redirige sus peticiones automáticamente al endpoint seguro HTTPS https://stocklimp-backend.onrender.com/api cuando no se encuentra en modo __DEV__.

6.3. Guía Rápida de Comandos para Mantenimiento

# 1. Iniciar el Backend Laravel localmente:
cd back
php artisan serve --port=8000

# 2. Iniciar el Frontend Expo en modo Web:
cd front
npm run web

# 3. Levantar todo el stack con Docker:
docker-compose up -d --build

# 4. Exportar o restaurar la Base de Datos:
mysql -u root stocklimp < "Base de datos/bbdd.sql"
